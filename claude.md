# claude.md

skill-tree aggregates open datasets to build a skill prerequisite graph. See
`TODO:` comments and readme `TODO:` items for the backlog, `research.md` for
prior work, and `readme.md` for the dataset catalog, schemas, stage details, and
build files.

## Commands

- `deno run -A pipeline.ts [stage]` runs one stage, or every stage in order.
- `deno task check` — fmt, lint, typecheck.
- `deno task test` — runs stage `list` for real (no Ollama) in a temp dir, on
  every source but a fixed sample of 200 CSP sets, and asserts on its output,
  plus fixture runs of the other stages. Keep it under 10 s: start each fixture
  run at module load so the runs overlap.
- `deno task status` — grades the last full build; exits 1 when any condition
  scores below 1.0. snitch runs it hourly.
- `data/download.ts` downloads all datasets and skips existing files:
  `deno run --allow-read --allow-write --allow-net --allow-run data/download.ts`
- Run `gzip -dc data/certatlas/exams.json.gz | jq length` for the exam count.

## Rules

- Ollama runs at `localhost:11434` for embeddings. Stages `enrich` and `prereq`
  send prompts through the Claude Batches API (`resumableClaude`, `lib.ts`) and
  need `ANTHROPIC_API_KEY`. Each in-flight batch id sits in `<cache>.batches`,
  so a rerun collects it instead of paying again.
- Errors: a missing build file names the stage that writes it. A missing cache
  reads as empty. Any other read error, a ragged TSV or CSV row, or an Ollama or
  Claude call that fails twice stops the stage.
- Build tables: each TSV that one stage writes and a later stage reads has one
  schema in `lib.ts`. `readTable` and `writeTable` check every cell, the header,
  the key, and the final newline. `writeTable` writes `path.tmp`, then renames.
  Stages `postproc` and `finalize` throw on an id outside
  `3b_tagged_deduped.tsv`. A new build table gets a schema; a new id goes
  through `slugify`.
- `SKIP_LLM=1` reuses the caches, less the stale rows, for a regression build
  without the generator. It rewrites the four caches without the stale rows;
  before a commit, restore the paid rows with
  `jj restore build/5_prereqs.tsv build/5b_expand.tsv build/5c_snap.tsv build/5d_testable.tsv`.
- The version sits in one constant, `LC_VERSION`, in `data/download.ts`.
- Git tracks the gzips, because jj refuses a new file over 1 MiB. (BNCC.)
- Uncompressed .csv files are gitignored. (`data/courses/`.)
- Oak: The API at open-api.thenational.academy needs `OAK_API_KEY` and allows
  1000 calls an hour, so `data/download.ts` crawls one file at a time and
  resumes.
- Skills England: Needs `DWP_OCC_API_KEY` (header `X-API-KEY`).
- Licences: the Junyi and LectureBank data stay gitignored.
  - Occupational maps API, OGL v3; every derived product shows the Skills
    England logo and its attribution (readme).
  - Data CC BY 4.0: credit "bncc.dev (maintained by Profy)" with a link to the
    repo.
  - The licence bars commercial use, so git does not track it, and no stage
    reads it: `deno task status` grades the edges against it.
  - A DataShop login downloads it by hand (tab Files).
  - The repo states no licence, so git does not track the clone;
    `data/download.ts` clones it (depth 1).
  - Stage `seed-edges` does not read it: the pairs are held out for
    `deno task status`.
- Stage `enrich` translates each `texto` with Claude into
  `build/1g_bncc_translate.tsv`, keyed by code. Stage `list` throws on a code
  with no translation.
- Stage `enrich` asks Claude whether each CSP set reads as English
  (`build/1h_csp_english.tsv`, keyed by set id) and translates the standards of
  each set that does not (`build/1i_csp_translate.tsv`, keyed by standard id).
  Stage `list` throws on a set with no answer, or a standard with no
  translation.
- A source that gives both A → B and B → A loses both, as does a course pair
  inside a seed cycle (`contested-order`): expert sources outrank course
  catalogs.
- Two groups whose `grade:*` tags share no grade never merge: they are two steps
  of a progression.
- Generated by `pipeline.ts` into the project root. Gitignored. (`skills.tsv`,
  `skills.tsv.gz`, `build/`.)
- Strict DAG, no self-loops, all IDs resolve within the file. (`prereqs` in
  `skills.tsv`.)
